# Правила работы с проектом ИВС-СЕТИ

## Перед началом

1. Прочитать `README.md`, `HANDOFF.md` и актуальные документы в `docs/`.
2. Проверить `git status --short --branch` и `git log -5 --oneline`.
3. Получать удалённые изменения без перезаписи локальной работы. Не делать `reset --hard`, не откатывать и не смешивать чужие изменения без разрешения владельца.
4. Для локального запуска использовать `npm run local`. Сайт работает на локальных данных без ключей Supabase.

## После каждой завершённой пользовательской задачи

1. Проверить результат в браузере, если менялся интерфейс.
2. Выполнить `git diff --check`. Для изменений кода также выполнить `npm run build`.
3. Проверить `git status --short`: в коммит не должны попасть `.env.local`, секреты, `node_modules`, `.next`, временные файлы и логи.
4. Добавить все относящиеся к задаче файлы через `git add -A` и создать осмысленный коммит на русском языке.
5. Версионируемый `.githooks/post-commit` автоматически выполнит `git push origin HEAD` для текущей ветки.
6. Убедиться по `git status --short --branch`, что локальная ветка не опережает удалённую. Если push не удался, исправить доступ или сеть, выполнить `git push origin HEAD` и честно сообщить владельцу результат.

Не ограничиваться сообщением «готово» без коммита и подтверждённой отправки. Если задача специально оставлена незавершённой или владелец попросил не коммитить, явно указать это.

## Запрещено

- Коммитить пароли, токены, приватные ключи и локальные `.env`, кроме `.env.example` с пустыми значениями.
- Менять факты компании без источника и перерисовывать готовый логотип.
- Перезаписывать изображения под тем же именем из-за кэша Safari: новая версия получает новое имя.
- Оставлять запущенные временные серверы и проверочные скрипты после завершения работы.
