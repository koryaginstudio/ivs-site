# Структура административной панели ИВС-СЕТИ

> **Легенда:** 🟢 согласовано с заказчиком (письма/ТЗ) · 🟡 не решено или есть противоречие · 🔴 наше допущение — на согласование

Требования из переписки: 🟢 сотрудники сами редактируют контент без программиста (ТЗ 18.09); 🟢 по возможности меняют структуру страниц — «большая часть сайта на конструкторе, возможность изменения структуры» (письмо 24.09); 🟢 независимость от одного разработчика (письмо 24.09).

## Роли и доступ 🔴

Сами роли и механика входа — моя проработка, в переписке не обсуждались.

| Роль | Что может |
|---|---|
| Администратор 🔴 | Всё: пользователи, настройки, структура, контент |
| Редактор 🔴 | Контент: новости, мероприятия, проекты, страницы, медиа. Без доступа к настройкам и пользователям |

Вход: логин/пароль, сброс пароля по почте, сессии с авто-выходом. 🔴 Двухфакторка — опционально на этапе внедрения.

## Ключевые принципы реализации

1. 🟢 **Контент отделён от кода.** Следует из требования независимости (24.09) и обещания хранить код в репозитории компании на GitHub (09.10). 🔴 Конкретика: БД (SQLite/PostgreSQL на ВМ заказчика).
2. 🟢 **Конструктор, а не свободная вёрстка.** Прямой запрос заказчика (24.09). 🔴 Формулировка «сломать вёрстку невозможно, новые блоки добавляет разработчик» — наша интерпретация.
3. 🔴 **Предпросмотр до публикации.** Черновик по секретной ссылке — наше дополнение.
4. 🔴 **Версионирование.** История изменений с откатом — наше дополнение.
5. 🟢 **Простота передачи.** Стандартный стек без экзотики — обещано заказчику (09.10). 🔴 Конкретика: админка — часть того же Next.js-проекта, отдельный маршрут.

## Что НЕ входит в админку (осознанно)

- 🟢 Формы обратной связи и их обработка — исключены требованием заказчика (24.09).
- 🔴 Интернет-магазин, корзина, личные кабинеты — наше уточнение рамок, логичное, но не обсуждалось.
- 🔴 Редактирование дизайн-токенов (цвета, шрифты) — наше решение зашить их в дизайн-систему, чтобы исключить развал визуала. 🟡 Заказчику может хотеться управлять цветами — стоит проговорить.
